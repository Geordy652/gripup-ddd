GripUp — Modélisation & Implémentation Domain-Driven Design (DDD)Projet réalisé dans le cadre du TD de Domain-Driven Design (Master 1 Informatique).Sujet : Conception du modèle de domaine et implémentation du cœur métier d'un réseau de salles d'escalade (GripUp : Centre, Euralille, Villeneuve-d'Ascq).1. Découpage Stratégique (Bounded Contexts)L'Event Storming a permis de découper le métier en 5 Bounded Contexts distincts afin d'isoler les responsabilités, les cycles de vie et les homonymes du glossaire (Abonné, Séance) :Package JavaContexte MétierType de sous-domaineResponsabilité principalefr.td.reservationRéservation & CapacitéCore Domain (12/12)Gestion des créneaux de 2h, capacité max de 60 grimpeurs/espace (G2), quotas de réservations (G3, G4), absences à +30 min (G7), annulations tardives (G8) et sanctions de 7 jours (G9).fr.td.coursCours & PédagogieSupporting (10/12)Planification des cours collectifs (8 max, G10), trajets moniteurs (G12), liste d'attente à délai de 2h (G11) et habilitation passeport tête (G13).fr.td.formulesFormules & FacturationSupporting (10/12)Gestion des cartes 10 entrées et abonnements (G1), décompte d'entrées (G6), suspension sur impayé (G17), gestes commerciaux (G18) et export comptable CSV.fr.td.membresMembres & Contrôle d'AccèsSupporting (7/12)Inscription des grimpeurs, accompagnement des moins de 14 ans (G15), cycle de vie des badges et anonymisation RGPD à 3 ans (C3).fr.td.notificationsNotificationsGeneric (4/12)Orchestration des envois de SMS (confirmations, liste d'attente, annulations) via le prestataire externe TextoPro.2. Points clés de l'implémentation (Étape 3)Séparation des modèles par contexte (Un mot, deux modèles) :Le concept de Grimpeur n'est pas partagé entre les contextes. Il est modélisé indépendamment dans fr.td.reservation.Grimpeur (quotas, délais de réservation, sanction G9) et dans fr.td.formules.Grimpeur (type de formule, solde d'entrées, suspension G17), reliés uniquement par leur identifiant (GrimpeurId).Événements du Core (fr.td.reservation) :Les commandes métier du cœur de domaine produisent des événements immuables nommés au passé (record Java) lorsque les règles métier sont validées :CreneauReserve (règles G3, G4, G9)GrimpeurNoteAbsent (règle G7)CreneauAnnule (règle G8)Anti-Corruption Layer (fr.td.formules.acl) :PaySurTraducteurACL isole le domaine GripUp du prestataire externe PaySûr en traduisant ses codes techniques (PAID, FAILED_NSF...) et ses montants en centimes vers des objets du domaine (ResultatPaiement, MontantEuros, MotifEchec), tout en rejetant explicitement tout code inconnu.3. Prérequis et exécution des vérificationsPrérequisJava 21 (ou Java 17+)Maven 3.8+Compiler le projet et exécuter les vérifications (-ea)Les vérifications reposent sur les assertions natives de Java (assert). Pensez à activer l'option -ea (enable assertions) lors de l'exécution :# 1. Cloner le dépôt
git clone https://github.com/Geordy652/gripup-ddd.git
cd gripup-ddd

# 2. Compiler les sources
mvn compile

# 3. Lancer les vérifications du Core (Réservation & Événements)
java -ea -cp target/classes fr.td.reservation.VerificationReservation

# 4. Lancer les vérifications de l'ACL PaySûr et des Formules
java -ea -cp target/classes fr.td.formules.acl.VerificationACL
Résultat attenduOK : 3 événements du Core (CreneauReserve, GrimpeurNoteAbsent, CreneauAnnule) vérifiés.
OK : Modèle formules + ACL PaySûr vérifiés.
